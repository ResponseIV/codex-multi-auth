# v2.17.3

Maintenance release landing an eighteen-PR review-and-hardening stack: every
merged change went through adversarial re-review, and the fixes below include
both the externally flagged findings and additional defects surfaced by
stress testing the stack as a whole.

## Security

- OAuth log redaction now covers bearer-first token ordering, URL fragments,
  flat nested query values, encoded and double-encoded separators, token-like
  hostnames, credential suffixes, and secrets smuggled as JSON key names;
  chunked entropy scrubbing avoids regex overflow on multi-megabyte payloads
  ([#719](https://github.com/ndycode/codex-multi-auth/pull/719)).
- Trust is enforced at library boundaries: audit logs and rotated backups are
  re-asserted `0600`, malformed local-client token digests are rejected,
  non-email `@` identifiers are no longer mangled as addresses, Windows
  root-relative binary overrides are refused on both `\` and `/` roots, and
  `AbortSignal.any` replaces a listener-leaking signal combiner
  ([#710](https://github.com/ndycode/codex-multi-auth/pull/710)).
- Overlong email labels can no longer defeat partial masking — the pattern is
  boundary-anchored and linear on multi-megabyte inputs — and timeout values
  above the 32-bit timer ceiling no longer clamp to near-zero instant failover
  ([#721](https://github.com/ndycode/codex-multi-auth/pull/721)).

## Fixes

- Cross-process governance stores (`account policy`, `budget`, `routing
  profiles`) now mutate under the proven directory lock with compare-and-swap
  retry: mutations re-apply to the freshest record under lock, dead-owner
  cleanup can never evict a live holder, and `dirty:false` skips no-op writes
  ([#713](https://github.com/ndycode/codex-multi-auth/pull/713)).
- Clock skew can no longer lose writes: quota observations keep the higher
  stamp when a raced key re-lands, and baseline-aware config merges let
  deliberate edits land against the freshest disk record while baseline-less
  saves keep last-writer-wins compatibility
  ([#723](https://github.com/ndycode/codex-multi-auth/pull/723)).
- Backup rotation keys on credential signature (account count plus refresh
  token set) instead of count alone, so a `.bak` holding a still-spendable
  token is never discarded early; chained rotations keep intermediate pending
  auth entries so a restored backup self-heals, and foreign writes are
  detected by content fingerprint
  ([#712](https://github.com/ndycode/codex-multi-auth/pull/712)).
- V1→V3 migration preserves V3-era and unknown fields, existing
  `rateLimitResetTimes` maps, and `activeIndexByFamily`; the strict schema no
  longer strips hybrid rows before migration, and orphaned tool-output
  normalization reads `output` once before the exception path
  ([#717](https://github.com/ndycode/codex-multi-auth/pull/717)).
- Budget and routing-profile merges treat `constructor` and `__proto__` keys
  as plain data via null-prototype maps — they can no longer silently drop
  limits or hit the prototype setter
  ([#714](https://github.com/ndycode/codex-multi-auth/pull/714)).
- The wrapper relays repeated signals until the forwarded child closes, sweeps
  only dead-owner shadow homes (child PIDs are marked and owner identity is
  verified by start time), and finalizes force-kill timers after `close`
  ([#720](https://github.com/ndycode/codex-multi-auth/pull/720)).
- Active-account sync fingerprints canonical storage plus every official
  mirror file, so a forwarded `codex login`/`logout` can no longer leave the
  mirror stale while the fast path reports clean
  ([#711](https://github.com/ndycode/codex-multi-auth/pull/711)).
- Reset-credit checks discover the relocated ChatGPT desktop backend
  (`codex-cli/bin/codex` layout before the legacy one), require bundled
  candidates to be executable files, surface partial refresh failures with
  exit 1, and reject ambiguous duplicate account identities before any
  credential read or redemption
  ([#724](https://github.com/ndycode/codex-multi-auth/pull/724)).

## Performance

- Account dedup maintains incremental identity indexes instead of rescanning
  the pool on every operation ([#708](https://github.com/ndycode/codex-multi-auth/pull/708)).
- Runtime policy stores are cached per request with fingerprint validation
  (mtime + ctime + size, post-load stability recheck, ancestor-directory
  tracking), and one ledger summary is shared per evaluation
  ([#709](https://github.com/ndycode/codex-multi-auth/pull/709)).
- Request transformation allocates less on the hot path: a fused clone path
  with descriptor-level inspection (getters, proxies, `required: []` fall back
  to the legacy path safely) and a non-throwing circuit-breaker probe
  ([#716](https://github.com/ndycode/codex-multi-auth/pull/716)).
- Backup rotation is throttled and baseline-less saves carry a content-hash
  fingerprint so recovery reads do not consume the foreign-write warning
  ([#712](https://github.com/ndycode/codex-multi-auth/pull/712)).

## Packaging and build

- `skills/` now ships in the tarball, and the `brace-expansion` security pin
  is a live npm override (self-reference form) instead of dead configuration
  shadowed by a sibling key
  ([#722](https://github.com/ndycode/codex-multi-auth/pull/722)).
- Tarball is smaller, typecheck is faster, and forward-path imports are
  slimmer ([#711](https://github.com/ndycode/codex-multi-auth/pull/711)).

## Tests

- Property suites now cover storage, transformer, SSE, budget, and redaction
  round-trips with a sorted-multiset oracle sound under duplicate ids, plus
  hardened generators for prototype-member keys
  ([#714](https://github.com/ndycode/codex-multi-auth/pull/714)).
- Chaos suites add real filesystem/network fault injection and live
  concurrency coverage; the harness now drains IPC on `close`, guards
  post-death `child.send()`, and attaches `error` listeners to destroyed
  socket responses ([#715](https://github.com/ndycode/codex-multi-auth/pull/715)).

## Docs

- Living documentation rewritten from the audited architecture: privacy-wipe
  recipes cover the right artifacts, per-project storage docs reflect
  CLI-forced global scope, outbound-traffic claims are accurate, `unpin`
  behavior vs forced launch pins is documented, and stale anchors/env names
  are corrected ([#718](https://github.com/ndycode/codex-multi-auth/pull/718)).
